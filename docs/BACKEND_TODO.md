## Decisions

- 2026-10-17, Manual SOA entries (§13.31): **both options**. Each entry is either **SOA only** (default: a line on the statement, balances unchanged, the SOA shows the difference) or **Changes the balance** (it also records a real transaction of the matching type, so the balance and every balance screen change). ## App shell notes (build step 3)

What the Phoenix backend must match so the screens need no change:

- **List queries** (`POST /{list}/query`): the mock's engine in `mock/src/lists/engine.ts` is the reference for semantics. Text operators are case-insensitive (`ILIKE`, `lower()`); `like` uses `%` / `_` with backslash escape; `regex` is POSIX case-insensitive (`~*`), and a pattern PostgreSQL rejects answers 400; negative operators (`neq`, `not_like`, `not_in`) keep rows whose value is empty; every sort ends with the record ID as tie-breaker; quick search matches the list's text columns. The mock's cursor is an offset; the backend may use keyset paging as long as the cursor stays opaque.
- **Field catalogues** (`GET /meta/lists/{list}/fields`) drive the grid's column filters and the filter builder; adding a field to a list needs no screen change.
- **Undo** (`POST /changes/{id}/undo`): restores only the fields the change touched; a later change by another user to the same record and field (not itself undone) is a conflict; undo of `create` archives the record, undo of `delete` restores it; the undo is a new change with `undo_of_id`; a change can be undone once (400 afterwards); undoing someone else's change needs the `undo_others` permission (403 otherwise).
- **Live socket**: `/socket/websocket?vsn=2.0.0`, Phoenix Channels V2 frames. The shell joins `live:tps` (tick once a second) and `alerts:<userId>` (incidents). The browser opens one socket in the main window and relays it to tabs dragged into other windows.
- **Workspace**: the GUI saves the open tabs (path, title, pinned) about a second after each change; page state (filters, sort, columns) is inside each tab's path.

## Rate Manager notes (build step 4.2)

- **Versions, never edits in place** (§6.2, §13.29): a new rate from `effectiveFrom` closes the version valid then (sets `valid_to`) and opens a new one; versions starting at or after that date are replaced. `effectiveFrom` can't be in the past (one minute of clock skew allowed), so traffic already sent keeps its rate (§13.32). Closing a scheduled line withdraws it and the version before it runs on as long as the withdrawn one would have. Blocking flags the line in place.
- **Change log** for rate edits: entity `rate_table`, record id = the table, one diff entry per touched line with field `line` and full line snapshots before/after (null = the line didn't exist). Undo deletes, then updates, then inserts, so no two versions of a destination overlap at any step (the exclusion constraints stay on). A line edited twice in one batch collapses to its first and last state. An undo change lists the same record ids as the change it undoes, and its entries run in reverse order.
- **Notice period** (§13.14): an increase on a customer table that starts sooner than the longest `rate_notice_days` among the clients using the table answers 409 with the breaches; `acceptNoticeBreach` applies it and the change note says so. New destinations and decreases are never a breach. Vendor tables have no check.
- **Best buy** = the cheapest rate valid now for the same MCCMNC and product category among live, active vendor trunks, without sender-ID or blocked lines, converted through the latest exchange rate (`best_buy_rates`). The backend should keep it current on every vendor rate change and when scheduled rates start; the mock refreshes it after vendor edits and every 5 minutes (about 3 s at full volume). `rate_table_stats` holds the per-table counts the list sorts on: refreshed for one table after its edits and for all after a best-buy refresh.
- **Traffic figures** (avg margin weighted by today's volume, revenue or cost today) come from the EDR store: customer tables by `c_rate_table_id`, vendor tables by `v_rate_table_id`, today in the platform time zone. They are null when the EDR store doesn't answer, and not filterable or sortable (no operators in the field catalogue).
- **Database settings**: integer list filters compare as `bigint` so they use the ID indexes (a `numeric` cast made `rateTableId = n` scan all 1.4 M lines), and JIT is off for API connections (it added 2 s of compile time to list queries with many small subqueries).
- Not in this step: rate import wizard and rate notices to clients (§12.1, §13.13; the buttons show disabled), Bulk rating opens the bulk workspace (§13.11, build step 5).

## Route Rules notes (build step 4.3)

- **Saving** (§6.3, §13.10): `PUT /route-rules/{id}` takes the whole rule; the change records only the fields that differ (vendors and whitelists as whole lists), so undo restores them. A save that changes only `status` is logged as `enable` / `disable`. The GUI saves one condition or one vendor edit at a time, so each is one undoable change.

Then vendor choice: number whitelist → warm-up threshold → hunt policy (percentage split, top down, round robin) for static rules, cheapest first for dynamic, quality score for QBR; vendors leaving less than `margin` (flat) or the revenue condition's minimum margin are skipped, and so are vendors at `skipVendorAtTpsPct` of their TPS. The backend should feed this from the live counters (Redis) instead of a periodic query. Without the EDR store the figures are null and the traffic endpoint answers `available: false`.

## Invoices and vendor invoice notes (build step 5.6)

- **Invoice balances** use the §7 sign like every balance: opening = the client's balance before the invoice date, closing = opening − usage charges, due amount = the owed part of the closing balance (never negative). ## Number lists and Translation rules notes (build step 5.3)

A block ends the run; a matched rule set to Stop ends it too. A matching rule applies, in order: sender conversion, receiver conversion (the network is looked up again), TON / NPI, billing type, registered delivery, the first matching DLR conversion, content rewrite (Regex Index group or the whole match), then the MSG Template (`{text}` = the text so far). Duplicate to trunk makes an active copy that targets that trunk only and takes the original's place there (same position and Continue); the original is switched off on that trunk only and keeps running everywhere else. ## Route map, Re-rating and QBR notes (build step 5.2)

- **Route map** (scope confirmed 2026-10-17): per customer trunk, every destination with a sell line in its rate tables, run through the live rules in order as a message without receiver or content (no warm-up, no number whitelists: the steady-state route). Same engine as Rate Lookup and the rule simulator. The mock computes a trunk's map in about 0.5 to 2 s and keeps it a minute; the backend should precompute it per trunk on rule and rate changes.
- **Routing speed-ups (mock)**: rules are indexed by destination code, rule time windows and vendor scopes are parsed once, and vendor costs per destination are cached a minute (cleared on rate changes and undo). A country-level code is now costed with each vendor's country line only, never a network's.
- **Re-rating**: EDRs billed with the request's rate table in the period (UTC days) are grouped by enterprise, destination, billed rate and hour and re-priced with the table's line valid at that time; a back-dated line counts from its stated date, which is how a back-dated RN rate is applied after all (§13.32). Billable units are `msg_count` where the EDR was billable. The difference per enterprise is a Reprocess note: customer, lower amount = credit note; vendor, lower cost = debit note. "No note" computes only. EDRs are never changed (§13.29). Requests are logged in the change history but not undone (maker-checker workflow). The mock runs the job in the background a moment after approval; the backend should use the job queue with progress.
- **QBR stats**: the window is the last 24 hours of EDRs (confirmed 2026-10-17). ADD = average delivery delay of delivered messages. A manual vendor stat wins until cleared; QBR rules order vendors by the destination's effective DLR, else the vendor's 7-day DLR.

## Product reference data notes (build step 5.1)

- **Imports** (§6.1 import modals) always run as a dry run first in the GUI; the same request with `dryRun: false` saves all or nothing, as one change that Undo reverses (rows added are archived again, rows changed get their old values, rows archived come back). Up to 200 errors, remarks and kept rows are listed. CSV may use commas or semicolons.

- **Safe delete** (§13.29): a product category is blocked while trunks, rate tables, route rules or translation / HLR rules use it; an MCCMNC code while rate lines, rules, dial codes or MO numbers use it (its 30-day traffic is shown, not blocking). Countries are not deleted. Restore is for administrators, as for other records.

## Enterprise report notes (build step 4.5)
